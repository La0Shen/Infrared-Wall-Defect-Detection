# wall-defect-single

外墙热红外缺陷检测 · **方案一(单帧基线管线)**。
从 `thermal-inspection` 项目剥离出的独立单帧版本(不含多时相/PCA/配准)。

## 内容介绍

基于无人机热红外照片(R-JPEG)检测外墙空鼓与渗水。单帧管线:

- **方案一(基线)**:单帧 → 发射率校正 → 去噪 → 去趋势 → MAD 噪声估计
  → z 分数阈值 → 斑块 → 特征提取 → 规则分类(窗户/空鼓/渗水/复核)。

识别为窗户后,整个窗户区域不作为识别条件:掩膜按外接矩形填充后自适应生长
覆盖去噪/导热造成的过渡带,用 NS 修复谐波填平背景,第二遍在净墙上检测。

## 识别原理:为什么看温度图就能判断空鼓/渗水

热像仪把每个像素的红外辐射换算成温度,得到一张温度图。外墙的两类缺陷之所以能在温度图上
"显形",是各自不同的热物理机制造成的:

### 空鼓 → 热斑(warm)

1. **正常墙面**:太阳辐射被饰面层吸收后,能通过粘结层**传导进基层墙体**。混凝土基层热容
   极大,是个"热汇",把热量迅速吃掉,表面温升有限。
2. **空鼓处**:饰面层与基层之间夹了一层空气。空气导热系数约 **0.026 W/(m·K)**,比混凝土
   (≈1.5)和砂浆小近两个数量级,这层空气把饰面层与基层**热隔离**——热量进得去、散不掉,
   在饰面层表面**积聚**。
3. **结果**:同一时刻空鼓处表面温度**高于**正常墙面,温度图上表现为**热斑**。

**必须在温度快速变化的时段拍**:温差来自"热量进出被阻断"这个动态过程;一旦墙面温度趋于
稳定(久晒后的正午、阴天),空鼓与正常墙面温度接近,缺陷就"沉"下去了。这正是本方案
"**晴天下午抓空鼓**"的由来,也与行业标准对检测时段的要求一致(见下文出处)。

### 渗水 → 冷斑(cold)

1. **热惯量增大**:水的比热容(≈4.2 kJ/(kg·K))远高于空气和干砌体,湿墙体的热容与导热
   系数都显著升高 → 白天吸热**升温更慢**。
2. **蒸发吸热**:表层水分蒸发带走汽化潜热(≈2450 kJ/kg),直接给墙面降温。这一项通常比
   第一项更主要。
3. **结果**:渗水处表面温度**低于**干燥墙面,温度图上表现为**冷斑**。

同样要抓时机:雨后墙体还湿、蒸发旺盛时最明显,即"**雨后清晨抓渗水**"。

> **一个反向效应**:夜间热惯量项会把湿墙推向偏暖,与始终偏冷的蒸发项方向相反。所以渗水
> 不是任何时候都偏冷,要以**雨后蒸发旺盛的时段**为准——这与空鼓的"符号随时相翻转"是对称的。

### 为什么还必须专门排除窗户

窗户在温度图上**同样表现为冷斑**,与渗水**同号**,不排除就会被大量误报成渗水——这是本项目
`window_mask` 存在的唯一理由。主因是**朝向**:玻璃反射天空的冷辐射,测温读到的是被拉低的
**表观**温度(不是真实温度);其次是玻璃热容小、与室内耦合。**发射率不是主因**——玻璃
ε 约 0.84~0.92,与砂浆/瓷砖的 ≈0.90 本来就很接近。

### 每一步工程手段各管一类干扰

规范要求判定时必须排除:饰面色差、表面污染、基层材料差异、**日照不均**、**内凹角热堆积**、
室内冷热源。本管线每一步正好各管一类:

| 工程手段 | 对付哪类干扰 |
|---|---|
| **去趋势**(减高斯模糊背景) | 日照不均造成的整墙大尺度温度梯度 |
| **窗户掩膜** | 玻璃/窗框这类固定构造(与渗水同号的冷斑) |
| **边界带**(照片最外一圈当作墙) | 画面边缘的未知构造与边界伪影(窗外未拍全等) |
| **ΔT 阈值 + 形状特征** | 色差、污染等"长得不像缺陷"的异常 |

### 出处

上述原理与阈值口径参考以下标准与文献;具体数值以现行正式文本为准。

- **JGJ/T 277-2012《红外热像法检测建筑外墙饰面粘结质量技术规程》**(行业标准)——本项目
  空鼓识别的直接依据。给出空鼓定义(饰面层与基层之间、或饰面层内部各层材料之间因粘结不牢
  而出现的分层)与检测方法,其 **§4.2.1 现场检测环境条件**要求:宜选晴天、低风速(风速
  不宜大于 4 m/s)、**被检测外墙的热辐射或环境温度宜处于快速升高或降低的时段**、待测区域
  不应有明水。本项目"晴天下午抓空鼓"(抓升温段)即对应这条"快速升高"的要求。
  (该规程 §4.2.2 另有一份九项影响因素清单,与下面的排除因素表不是同一份。)
- **CECS 204-2006《红外热像法检测建筑外墙饰面层粘结缺陷技术规程》**(协会标准,现为团体
  标准,现行)——空鼓检测的同业规程,常与 JGJ/T 277 并用。其适用范围**不包括**大凹凸/拉毛
  墙面与高反光饰面,这也界定了本方法的边界。
- **饰面层粘结缺陷分级与数据处理标准**(CECS 系列)——"**直接日照立面局部温差大于 1℃、
  或无日照立面局部温差大于 0.5℃ 时可判定存在缺陷,但应排除饰面色差、表面污染、基层材料
  差异、日照不均、内凹角热堆积、室内冷热源等因素影响**"这一判定口径出自此处,不是
  JGJ/T 277 正文。本项目 `空鼓 ΔT > +1.5℃` 的初值即在此口径上取保守值;上表"每一步工程
  手段各管一类干扰"正是对这段"应排除"要求的逐条落实。
- **JG/T 269-2010《建筑红外热像检测要求》**——覆盖外墙饰面质量缺陷、渗漏与外围护结构热工
  缺陷的红外检测要求,渗漏现场检测宜参照。
- **ISO 6781-1:2023** *Performance of buildings — Detection of heat, air and moisture
  irregularities in buildings by infrared methods — Part 1: General procedures*
  (替代已作废的 ISO 6781:1983 *Thermal insulation — Qualitative detection of thermal
  irregularities in building envelopes — Infrared method*;对应欧洲标准 **EN 13187:1998**)。
  其原理表述为:围护结构热工特性的不连续会产生表面温度差异,据此可检出保温缺陷、
  **含湿量异常**与漏风路径——即本方案"空鼓看温差、渗水看湿区"的国际标准依据。该标准
  明确其方法为**定性**检测,结论应由受训人员判读。
- **ASTM D4788-03(2022)** *Standard Test Method for Detecting Delaminations in Bridge
  Decks Using Infrared Thermography*——红外热像法探测**分层/脱空**的经典方法标准
  (对象为桥面板,非建筑外墙,此处作为"脱空→热异常"方法学渊源引用)。

> 说明:本项目当前的分类与阈值是**工程初值**,并非直接照搬上述标准的数值;按 总体方案.md §7
> 的闭环,需现场锤击(空鼓)/湿度计(渗水)验证后回调,规范数值只作为量级参照。

## 环境要求与安装

- Python ≥ 3.8(开发环境 3.12,依赖 numpy / opencv-python / PyYAML)
- Windows + [DJI Thermal SDK](https://www.dji.com/cn/downloads/softwares/dji-thermal-sdk)
  (解析 R-JPEG 真实温度;未配置时自动退回灰度读取,仅用于开发调试)

```bash
# 创建并激活虚拟环境
python -m venv .venv
source .venv/Scripts/activate        # Git Bash
# .venv\Scripts\Activate.ps1         # PowerShell
# .venv\Scripts\activate.bat         # cmd

# 安装依赖
pip install -r requirements.txt                    # 必要依赖
pip install -r requirements-optional.txt           # 可选:pytest + DJI SDK 包
```

> 注意:pip 安装的 `dji-thermal-sdk` 只是 Python 封装,**不含原生 DLL**。
> 还需从大疆官网下载 DJI Thermal SDK 压缩包,解压出 `libdirp.dll`,并设置
> 环境变量 `DJI_DIRP_DLL` 指向其完整路径。未配置 DLL 时,`.jpg` 输入自动
> 退回灰度伪温度,并在 `summary.json` 的 `warnings` 中记录降级原因。

## 输出说明

分两处落盘(路径各有参数可改;标注图那处是**固定目录**,历次跑的都归拢在一起):

**结果数据** —— `data/output/<结果根>/<文件名>/`(默认结果根 `formal`):

| 文件 | 内容 |
|---|---|
| `temperature.npy` | 校正后的温度矩阵(℃,float32;已删除窗户区域) |
| `mask_NNN_<类别>.png` | 每个斑块的二值掩膜 |
| `defects.csv` | 缺陷清单:坐标、面积、ΔT、5 个特征、来源(source 恒为 single) |
| `summary.json` | 汇总:各类数量 + 参数快照(可复现);输入降级时含 `warnings`;开启绝对矩形掩膜时含 `rect_mask`(矩形清单,每条含粗边宽度 `edge_px`) |
| `rect_mask.png` | **仅**在 `rect_mask.enabled: 1` 时生成:绝对矩形掩膜图 |

**标注图** —— `data/output/images/<文件名>/`(每张输入图一个子文件夹,里面就只有这两张):

| 文件 | 内容 |
|---|---|
| `overlay.png` | 修复后(净墙)的温度伪彩 + 缺陷轮廓 + 标签(人工复核用;可用 `display` 段控制画哪些) |
| `overlay_preinpaint.png` | **修复前**的温度伪彩 + 同一套标注(窗户还没被填掉,看"拍到的样子") |

## 注意事项

- 分类为**规则分类(非机器学习)**:特征人工设计、阈值人工设定;机器学习方案见 `docs/延伸篇.md` §9。
- **窗户掩膜**:识别为窗户后,整个窗户区域不作为识别条件(窗户反光会造成窗内温度不均、大量虚假候选)。第一遍从 z 冷侧找窗户(单窗矩形 + 成排/成列的窗户区域块);掩膜按外接矩形填充后自适应生长覆盖去噪/导热造成的过渡带(`grow_tol_c`/`grow_max_px`),用 NS 修复谐波填平背景;第二遍在净墙上检测,与掩膜覆盖率超过 `exclude_overlap` 的候选斑块直接排除,控制台打印排除计数。参数在 `defaults.yaml` 的 `window_mask` 段,`enabled: false` 可关闭。
- 发射率校正采用斯特藩-玻尔兹曼近似(工程简化);严格做法为 8–14µm 波段积分与 SDK 标定,见 `docs/延伸篇.md` §10.4。
- `io.py` 按 PyPI 包 dji-thermal-sdk 0.0.2 的真实接口调用;若升级 SDK 大版本导致接口变化,需同步调整 `_read_rjpeg_dji`。
- **边界带(照片边界当作墙)**:`detect.border_ignore_px`(默认 15)把照片最外一圈视为墙,**那里不检测**——窗外未拍全、边界外无墙可比,会在边界产生大量伪影(实测 test01 有 12 个斑块挤在左边缘 `x=0`)。实现上只在**检测掩膜**上扣掉这一圈,不改像素值:实测四条边的墙面中位数相差 4.12℃,垫边填任何常数都会造出阶跃(实测垫边后斑块数 40→101→191),且会改变 MAD 噪声估计。
  **边界带是"检测口径"而非"形状口径"**:斑块只要在带内有足够像素就会被检出,但报出的形状取自它所属的**完整**连通域。原因是带会把斑块轮廓沿直线切直、把 `rect`/`elong` 人为拉高(实测同一斑块 rect 0.66→1.00、elong 1.91→6.00);回查完整连通域后,真正跑出画面的细长渗漏能按真实形状判出来,而边界切出来的直边不会被当成矩形。`0` = 不过滤。
- **形状渗漏规则**:`classify.seepage_rect`(默认 0.80)+ `seepage_rect_elong`(默认 2.0)——冷斑块只要**矩形度高且细长**即判渗漏,**不看 ΔT**(规则的矩形形状比温差更能说明问题,ΔT 阈值会漏掉形状确定的规则渗水)。纵横比取 `minAreaRect` 长轴/短轴(特征 `elong`,旋转不变),与 `seepage_elong` 是同一个量,只是分属两条规则。可选的 `seepage_shape_require_cold`(默认 false)开启后叠加 `seepage_shape_dt_c`(默认 −0.8)下限:实测 test01 上不开启会多出若干浅温差候选(边界处 `x=0` 的斑块 dT 多在 −0.2~−0.6),开启后只剩 3 个(含真渗水 dT=−1.70 与那条贯穿全高的渗漏 dT=−0.96),按现场情况决定。
- **窗区块长宽比**:`window_mask.aspect_min`/`aspect_max`(0.15/6.67,互为倒数)——"窗户区域块"(成排/成列的窗合并出的块)不能比这更细长,否则按渗漏交给检测层判。原值 0.08/12.5 放行了宽高比 0.131(长/宽 7.6)的贯穿全画幅细长冷条,被误当成窗区块。
- **绝对矩形掩膜(调试用)**:`rect_mask.enabled`(0=关/1=开)控制的**另一路找矩形**——把温度图按 `|T − median(T)| > dt_c` **转码**成二维二值矩阵(阈值是℃、双侧、不依赖噪声统计),再按几何(四边逼近恰 4 顶点 + 凸 + 四角近 90°)挑出规则**粗边**矩形,填充成掩膜后**掩埋**(膨胀 → NS 修复填平),沿用原方案继续去噪等处理。**`dt_c` 是主要旋钮,取值影响很大**:合成场景的 ΔT=−1.5℃ 方块 `dt_c=0.5` 就完整找到,demo 场景 `dt_c=3.0` 恰好找到那个窗,真实帧 `dt_c=1.0~3.0` 给出 3~4 个矩形、二值占比 26%→10%。**"粗边"(`min_edge_px`,默认 3.0)是后加的一条**:光有"恰 4 顶点",一条 1px 粗的细线框也会被当成规则矩形。量的是**最粗处**(2 × 最大内切圆半径)——粗边框量到带宽、实心块量到短边,**实心与粗边框都算**。量之前必须给二值矩阵**补一圈 0**:`cv2.distanceTransform` 不把画面外当背景,贴边的块会被量成整个宽度(实测 89px 宽量出 174px)。实测 1px 细线 = 2.0px、真实窗框/实心块 = 14~92px,**故该门槛在现有数据上从未生效过**,是防发丝细线的护栏而非主力判据。**另两个调试提示**:`approx_eps` 决定能否凑出"恰 4 顶点"(真实帧上 2% 会让窗户给出 6~10 个顶点而被否掉);清单条数不等于目标个数(目标内部有反差结构时会裂成多个四边,掩膜取并集仍正确)。启用时额外产出 `rect_mask.png` 与 `summary.json` 的 `rect_mask` 段(每条含 `edge_px`)。详见 `docs/总体方案.md` §2.6。
- **叠加图显示过滤**:`defaults.yaml` 的 `display` 段按类别控制 `overlay.png` 画哪些斑块——每类一个 0/1 开关(`show_window`/`show_hollow`/`show_seepage`/`show_reject`,0=不显示)加一个长度下限(`min_len_*_px`,边框 `max(宽,高)` 小于此值不画)。**只影响 overlay.png**:`defects.csv`、`summary.json`(含 `counts`)、`mask_NNN_*.png` 一律为全量,供复盘与追溯。`reject` 是兜底未分类,白框噪声多时设 `show_reject: 0`。overlay 上的编号沿用斑块在缺陷列表中的下标,与 `defects.csv` 的 index 列、mask 文件名一一对应,故隐藏后编号可能不连续(这是刻意的,便于对照 CSV)。
- `defects.csv` / `summary.json` 中的 source/component 列为单帧管线惰性默认值(source 恒为 "single"、component 恒为空),字段保留以兼容原项目输出格式。
