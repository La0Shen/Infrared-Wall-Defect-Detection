## 一、项目定位

**一句话**:基于无人机热红外照片(R-JPEG),自动检测建筑外墙两类缺陷——**空鼓**与**渗水**——的规则算法软件。

**业务背景(为什么要用热红外)**

- 外墙饰面层(瓷砖/抹灰)与基层脱开后形成**空气层**,即"空鼓"。空气层把饰面层与基层
  **热隔离**,饰面层失去基层这个热汇 → **热惯量小 → 对温度变化响应更快、幅度更大**。
  于是**升温时段**(白天)它比正常墙面**热**,单帧上表现为**热斑(warm)**;降温时段
  (傍晚/夜间)散热更快、反而**冷**于正常墙面(**符号随时相翻转**)。降温段温差更小、
  时间窗更窄且要求低风速,故现场仍以"晴天下午抓空鼓"为主。
- 雨水渗入墙体后,**水分蒸发吸热**,使该区域偏冷,且沿墙面流动形成**细长条带**,
  单帧上表现为**冷斑(cold)**。(水的比热容大还会让湿墙热惯量增大、白天升温更慢,同向偏冷;
  夜间该项反向,故渗水以雨后蒸发旺盛时段为准。)
- 无人机搭载热成像相机(大疆 Mavic 3T 等)拍摄的 R-JPEG 内含逐像素温度数据,
  一次飞行即可覆盖整栋楼外墙,替代人工敲击听响、吊篮作业等传统手段。

**本项目的实现范围**:总体方案.md 中的共用预处理(§1.2)、方案一基线管线(§2)、
特征提取与分类规则(§4)、参数表(§5)、验证回调(§7)。深度学习方案三
(延伸篇.md §9)等不在本仓库,属延伸方向。

**分类是规则分类,不是机器学习**:特征人工设计、阈值人工设定、现场验证后人工回调参数。

## 三、检测管线:方案一(单帧基线)

```
读取 R-JPEG → 温度矩阵 T(℃)
预处理:① 发射率校正(ε=0.90,斯特藩-玻尔兹曼近似)→ ② 3×3 中值去噪 → ③ GSD
窗户掩膜:识别窗户矩形 → 掩膜自适应生长覆盖过渡带 → NS 修复填平(区域不作为识别条件)
检测:  ① 去趋势 T_anom = T − 高斯模糊(T, σ=20px),σ ≈ 2~3×缺陷半径
       ② 稳健噪声估计 σ_noise = MAD(T_anom) × 1.4826
       ③ 标准化 z = T_anom / σ_noise
       ④ 阈值 |z| > 2.5 → 热斑(warm)/ 冷斑(cold)
       ⑤ 连通域提取,剔除面积 < 25px 的斑块
       ⑥ 与窗户掩膜覆盖率超过阈值的候选直接排除
特征 → 规则分类 → 输出 → 现场验证 → 回调参数重跑
```

**核心思想**:先"去趋势"把整墙的日照梯度(背景)减掉,只留局部异常;再用
MAD(中位数绝对偏差)而不是标准差估计噪声——因为异常斑块本身就是离群点,
标准差会被它们拉大,MAD 对离群值稳健。

## 四、核心模块详解

### 4.1 `io.py` — 温度数据读取

- `.npy`:直接读温度矩阵(演示数据/预处理产物)。
- `.jpg/.jpeg`(R-JPEG):优先经 **DJI Thermal SDK** 解析真实温度(开尔文 → 摄氏度);
  SDK 未安装或解析失败时**回退灰度读取**,仅供开发调试并打印告警。
  这是典型的"优雅降级"设计:真实业务不中断、开发环境不需要硬件 SDK。

### 4.2 `preprocess.py` — 共用预处理

- **发射率校正**(工程简化):`W(T_surf) = (W(T_meas) − (1−ε)·W(T_refl)) / ε`,
  用斯特藩-玻尔兹曼定律 `W = σT⁴` 近似。严格做法是 8–14µm 波段积分与 SDK
  标定曲线(延伸篇.md §10.4),此处为可复现的简化版,ε 统一取 0.90。
- **去噪**:3×3 中值滤波,去掉传感器椒盐噪声。
- **GSD**:`distance_m / 540`(Mavic 3T 经验系数),用于把像素面积换算成物理面积(m²)。

### 4.3 `detect.py` — 异常检测积木

| 函数 | 作用 |
|---|---|
| `detrend` | 原图减高斯模糊背景,消除整墙日照/朝向梯度 |
| `mad_sigma` | σ_noise = MAD × 1.4826(MAD 换成正态 σ 的系数) |
| `zscore` | z = x / σ_noise,零方差保护(σ=0 时置全零并告警,不再全图误报) |
| `threshold_z` | \|z\|>2.5 双侧:正 z=warm,负 z=cold |
| `extract_blobs` | OpenCV 连通域 + 最小面积过滤,返回掩膜/面积/bbox |

这 5 个函数是纯函数积木,只在去趋势图上用一次。

### 4.4 `features.py` — 5 个斑块特征

| 特征 | 定义 | 判别用途 |
|---|---|---|
| `dT` | 斑块均值 − 外围膨胀环带均值(局部温差) | 空鼓热、渗水/窗户冷 |
| `sharp` | 斑块内 \|拉普拉斯\| 均值(边界锐度) | 窗户边界锐利、空鼓弥散(可选开关) |
| `uniform` | 斑块内温度标准差(内部均匀度) | 均匀的几何体 vs 纹理缺陷 |
| `rect` | 面积 / 最小外接矩形面积(矩形度) | 窗户接近 1、空鼓不规则 |
| `elong` | 长轴/短轴(伸长率) | 渗水细长 |
| `verticality` | 长轴竖直度 0~1,由像素坐标 PCA 主方向算 | 渗水沿墙面竖直流(可选开关) |

细节:伸长率用 `cv2.minAreaRect` 返回的两边 max/min(其 (w,h) 顺序无保证);
竖直度不用 minAreaRect 的角度(角度约定易踩坑),而是对斑块像素坐标做 PCA
取主方向——这是"绕过 OpenCV 接口陷阱、自己用数学保证正确"的好例子。

### 4.5 `classify.py` — 规则分类(非机器学习)

四条规则,按序判定,命中即返回:

1. **窗户(非缺陷)**:矩形度高 + 明显偏冷(+可选"边界锐利");
2. **空鼓**(warm 斑块):偏热 + 形状不规则(+可选"边界弥散");
3. **形状渗漏**(cold 斑块,本项目新增):矩形度高 + 细长,**不看 ΔT**——
   规则的矩形形状比温差更能说明问题,ΔT 阈值会漏掉形状确定的规则渗水;
4. **渗水**(cold 斑块):偏冷 + 细长(+可选"长轴偏垂直");
5. 其余 → `reject`(交人工复核)。

定性条件(锐利/弥散/偏垂直)默认**关闭**,与 总体方案.md 伪代码保持一致;开启后与
全图平均边缘锐度 `sharp_ref` 做相对比较。"长轴偏垂直"开关对第 3、4 两条渗水
规则**都**生效,否则会被形状规则静默绕过。阈值全部在 `defaults.yaml` 的
`classify` 段,现场验证后回调。

另外两条与边界有关的规则:

- **边界带当作墙**:`detect.border_ignore_px`(默认 15)——照片最外一圈不参与
  检测(窗外未拍全、边界外无墙可比,会产生大量伪影)。只在掩膜上扣,不改像素值
  (垫边填充会因四边墙面温度不一致而造出阶跃)。
- **边界带是"检测口径",不是"形状口径"**:斑块只要在带内有足够像素就会被检出,
  但报出的形状取自它所属的**完整**连通域——被带切过的斑块外轮廓会被切直,
  `rect`/`elong` 会被人为拉高(实测 rect 0.66→1.00、elong 1.91→6.00)。这么做
  才能既清掉边界伪影,又让真正跑出画面的细长渗漏按真实形状被判出来。
- **窗区块的长宽比**:`window_mask.aspect_min/aspect_max`(0.15/6.67,互为倒数)
  限制"窗户区域块"能有多细长——比这更细长的按渗漏交给检测层判,避免贯穿全画幅
  的细长冷条被当成成排窗户合并出的区域块。

### 4.6 `pipeline.py` — 编排、窗户掩膜与输出

- `run_single`:唯一编排入口——预处理 → 窗户掩膜 → 检测 → 特征 → 分类 →
  输出,全部在净墙(窗户已删除)上进行;
- **窗户掩膜(本项目的亮点)**:识别出窗户矩形后,掩膜按外接矩形填充,再
  **自适应生长**覆盖去噪/窗框导热造成的过渡带(逐像素外扩,环带温度回到
  局部背景水平即停),用 NS 修复(谐波延续)把区域填成背景——Telea 修复在
  过渡带斜坡边界上会产生 ±1℃ 棋盘纹,不可用;第二遍与掩膜覆盖率超过
  `exclude_overlap` 的候选直接排除并打印计数;
- **输出**:`temperature.npy`(已删窗户的校正温度矩阵)、伪彩叠加图
  `overlay.png`(INVERNO 伪彩+轮廓+标签)、逐斑块掩膜 `mask_NNN_类别.png`、
  缺陷清单 `defects.csv`、汇总 `summary.json`(含完整参数快照,结果可复现)。
- **显示过滤(`display` 段,本项目新增)**:按类别控制 `overlay.png` 画哪些斑块——
  每类一个 0/1 开关(`show_window`/`show_hollow`/`show_seepage`/`show_reject`)
  加一个长度下限(`min_len_*_px`,边框 `max(宽,高)` 小于此值不画)。**只影响
  `overlay.png`**:`defects.csv`、`summary.json`(含 `counts`)、`mask_NNN_*.png`
  一律为全量。overlay 上的编号沿用斑块在缺陷列表中的下标,与 CSV 的 `index` 列、
  mask 文件名一一对应,故隐藏后编号可能不连续(刻意,便于对照 CSV)。

### 4.7 `demo.py` / `scripts/` — 演示与 CLI

- `scripts/make_demo_data.py`:合成含空鼓/渗水/软边窗户的温度图,无需无人机
  即可端到端跑通;
- `scripts/run_inspection.py`:CLI 入口,`--input` 指定单张图或目录(逐张处理),
  `--config`/`--output` 可覆盖默认路径。

## 五、关键工程设计与亮点

1. **参数集中 + 验证回调闭环**:全部旋钮集中在 `config/defaults.yaml`
   (dataclass + YAML 部分覆盖加载,未知键/非法 null 严格报错),现场验证后
   只改 YAML 重跑,`summary.json` 记录参数快照保证可复现。
2. **处处优雅降级**:DJI SDK 缺失→灰度;零方差→置零告警;minAreaRect
   异常→默认值。管线永不因单点失败而崩。
3. **纯算法与 I/O 分离**:`detect.py`/`features.py` 是无 I/O 的纯函数,编排和
   输出都在 `pipeline.py`,单测好写、逻辑清晰。
4. **测试覆盖**:70 项 pytest,含窗户掩膜过渡带删除、端到端(合成数据)。
   `conftest.py` 把 src 加入 sys.path。
5. **文档-代码-参数三方对应**:每个模块注释标 总体方案.md 章节号,
   `docs/算法说明.md` 与伪代码逐节对应,并明示"工程实现与伪代码的差异及理由"
   (如定性条件默认关闭、窗户删除的过渡带处理)。

### 阶段 3:窗户掩膜专题(1~2 天)

读 `pipeline.py` 的 `_window_mask` / `_grow_mask_to_background` /
`_inpaint_windows`,对照 `tests/test_pipeline.py` 的窗户掩膜 5 项测试。

重点吃透三个设计:

1. 为什么窗户反光会造成大量虚假候选、为什么要"整块矩形不作为识别条件";
2. 过渡带(去噪/导热造成的渐变区)为什么要自适应生长覆盖、停止条件为什么
   用"环带 vs 参考带"的局部比较;
3. 为什么修复用 NS(谐波延续)而不用 Telea(斜坡边界棋盘纹)或常数填充
   (人工边缘被下一段检测误判)。

- **练习**:用 numpy/cv2 手写一个最小化"过渡带残留"的实验:同一张软边窗图,
  分别用 Telea/NS/常数填充修复,对比第二遍检测的斑块数与 overlay 观感。
- **产出**:一份"窗户删除"的机理笔记,含修复算法对比图。

### 贯穿始终的方法论

1. **文档先行**:先读 `docs/算法说明.md` 与 总体方案.md 对应章节,再读代码——
   本项目的注释与文档章节号一一对应,是读文档练习的好材料;
2. **顺数据流读代码**:从输入到输出,一个函数进一个函数出,不跳读;
3. **对照测试读实现**:每个测试都是模块的"可执行规格说明";
4. **改参数做实验**:YAML 设计让"改一个数→看输出变化"的成本极低,多动手;
5. **追问"为什么这么设计"**:本项目大量注释写明了取舍理由(为什么 MAD、
   为什么 NS 修复、为什么自适应生长),养成记录设计理由的习惯。

## 八、常见疑问速答

- **为什么不用深度学习?** 规则方案可解释、可验证、数据需求小,适合冷启动;
  延伸篇.md §9 规划了方案三(深度学习增强)作为后续融合方向。
- **发射率校正准吗?** 是斯特藩-玻尔兹曼近似(工程简化),严格做法见
  延伸篇.md §10.4;对"相对温差"型缺陷检测,近似已够用。
- **没有 DJI SDK 能跑吗?** 能:`.jpg` 输入自动退回灰度伪温度并打印告警,
  演示流程用 `.npy` 完全不受影响;真实业务请配置 SDK 与 `DJI_DIRP_DLL`。
