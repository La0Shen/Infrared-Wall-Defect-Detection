# 如何开始:第一次跑通外墙热红外缺陷检测(方案一)

> 目标读者:第一次接触本项目的同学。按本文顺序操作,即可从零跑通方案一,
> 并知道每一步之后该看什么、下一步学什么。全程使用合成演示数据,**无需无人机与 DJI 设备**。

## 0. 动手前先知道

- 项目做什么:输入单张热红外温度图,输出外墙**空鼓 / 渗水**缺陷清单
  (以及窗户等干扰的排除结果)。
- 方案一(单帧基线):一张照片即可,去趋势 + MAD + z 分数阈值检测。
- 所有命令都在项目根目录(`wall-defect-single/`)下执行。
- 检测是**规则算法**(非机器学习),所有阈值都写在 `config/defaults.yaml`,
  改一个数、重跑一次,就能看到输出变化——这是本项目最好玩的地方。

## 1. 安装依赖(一次性)

```bash
pip install -r requirements.txt
```

安装内容:`numpy`、`opencv-python`、`PyYAML`。可选:

```bash
pip install -e ".[dev]"        # 加装 pytest,跑测试用
pip install -e ".[dev,dji]"    # 再加 DJI Thermal SDK 包(仅 Windows),解析真实 R-JPEG 温度
```

> 不装 DJI SDK 也不影响演示流程:读取 R-JPEG 时会自动退回灰度读取并打印告警,
> 仅供开发调试(不代表真实温度)。
>
> 装好 `dji-thermal-sdk` 包后还差一步:pip 包**不含原生 DLL**。请从大疆官网
> 下载 DJI Thermal SDK 压缩包,解压出 `libdirp.dll`,设置环境变量
> `DJI_DIRP_DLL` 指向其完整路径。未配置 DLL 时 `.jpg` 输入自动退回灰度,
> 并在 `summary.json` 的 `warnings` 中记录降级原因(见 §8 FAQ)。

验证安装:

```bash
python -c "import numpy, cv2, yaml; print('ok')"
```

打印 `ok` 即就绪。

## 2. 生成演示数据

```bash
# 单帧(方案一用)
python scripts/make_demo_data.py
```

生成内容:

| 命令 | 产物 | 说明 |
|---|---|---|
| 上一条 | `data/raw/demo/demo.npy` + `demo.png` | 单帧温度矩阵 + 预览图 |

演示数据里合成了三类对象:**空鼓(热斑)、渗水(冷斑)、窗户(干扰)**,
覆盖全部类别,方便观察分类效果。

## 3. 跑第一次检测

```bash
# 方案一:单张(目录则逐张处理)
python scripts/run_inspection.py --input data/raw/demo/demo.npy
```

控制台输出示例(具体数值随合成数据随机种子变化):

```
[处理] demo.npy(方案一)
  温度范围 22.0~30.4℃,检出 7 处: {'window': 1, 'reject': 4, 'hollow': 1, 'seepage': 1}
  结果: data/output/demo
完成
```

> 这里的"检出 N 处"是**含 reject 的全量**,不是你在 overlay 上看到的数量:
> `display` 段会把关掉的类别从图上省去(见 §5)。

## 4. 看懂输出

分两处落盘:

**标注图**(**最先看**)—— `data/output/images/<输入名>/`,每张输入图一个子文件夹,
里面就这两张:

| 文件 | 是什么 | 什么时候看 |
|---|---|---|
| `overlay.png` | **修复后**(净墙)温度伪彩 + 缺陷轮廓 + 类别标签(受 `display` 段控制) | 看最终判了什么,**人工复核用** |
| `overlay_preinpaint.png` | **修复前**温度伪彩 + 同一套标注(窗户还没被填掉) | 对照"拍到的原样",看窗户那块到底长什么样 |

**结果数据** —— `data/output/formal/<输入名>/`:

| 文件 | 是什么 | 什么时候看 |
|---|---|---|
| `defects.csv` | 缺陷清单:坐标/面积/ΔT/5 特征/来源(source/component) | 想逐斑块核对 |
| `summary.json` | 分类汇总 + **完整参数快照**(可复现) | 想确认当时用了什么参数 |
| `temperature.npy` | 校正后的温度矩阵(℃,已删除窗户区域) | 想二次分析 |
| `mask_NNN_类别.png` | 每个斑块的二值掩膜 | 想单独看某个缺陷 |

建议第一次按这个顺序看:`overlay.png` / `overlay_preinpaint.png`(整体)→
`defects.csv`(细节)→ `summary.json` 的 `counts` 与 `params`(复盘)。

## 5. 第一次调参

打开 `config/defaults.yaml`,改一个数,重跑第 3 步的命令,对比输出变化:

| 改动 | 参数 | 预期变化 |
|---|---|---|
| `detect.z_threshold` 1.5 → 0.8 | 敏感度 | 斑块明显变多 |
| `detect.min_area_px` 50 → 100 | 最小面积 | 小斑块被剔除 |
| `classify.hollow_dt_c` 1.5 → 3.0 | 空鼓判定 | 空鼓检出变严(变少) |
| `window_mask.grow_max_px` 10 → 0 | 窗户过渡带生长 | 关闭自适应生长,过渡带残留变多 |
| `detect.border_ignore_px` 15 → 0 | 边界带 | 照片最外一圈重新参与检测,贴边伪影回来了 |
| `classify.seepage_rect` 0.80 → 0.95 | 形状渗漏规则 | 只有更规整的细长冷斑判渗漏(变少) |
| `classify.seepage_shape_require_cold` false → true | 形状渗漏规则 | 额外要求 ΔT < −0.8,弱信号不再判渗漏 |
| `window_mask.aspect_min` 0.15 → 0.08 | 窗区块长宽比 | 放宽后贯穿全画幅的细长冷条会被当成窗区块掩掉 |
| `display.show_reject` 1 → 0 | 叠加图显示 | overlay 不再画 reject(白框噪声消失);CSV/summary/mask 不变 |
| `display.min_len_reject_px` 0 → 40 | 叠加图显示 | overlay 只画长边 ≥40px 的 reject;CSV/summary/mask 不变 |

所有参数都是初值;真实业务中按"现场验证(锤击听空响/湿度计)→ 统计检出率
与误报率 → 回调参数 → 重跑"的闭环(总体方案.md §7)进行。

## 8. 常见问题

| 现象 | 原因与处理 |
|---|---|
| `ModuleNotFoundError: No module named 'cv2'` | 依赖未安装,先执行第 1 步 |
| 打印"输入降级: … 退回灰度伪温度" | 未配置 DJI SDK/DLL,仅调试;真实业务请装包并设 `DJI_DIRP_DLL` |
| `summary.json` 出现 `warnings` 且 `level: degraded` | 该帧走了灰度伪温度(未装 SDK/未配置 DLL/非大疆 R-JPEG),缺陷温度特征不可信 |
| 想复现某次结果 | 打开 `summary.json` 的 `params` 快照,把值填回 YAML 重跑 |
