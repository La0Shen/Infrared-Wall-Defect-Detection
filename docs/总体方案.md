## 0. 总体架构

```
                 R-JPEG 辐射温度
                      │
              共用预处理(读温/发射率/去噪/配准)
                      │
        ┌─────────────┴─────────────┐
        │                           │
   方案一(基线)                 方案二(升级)
   单帧处理                     多时相+PCA
        │                           │
   去趋势→阈值→特征分类        PCA→分量选择→阈值
        │                           │
        └─────────────┬─────────────┘
                      │
              共用:特征提取/窗户掩膜/分类规则
                      │
              地面真值验证 → 回调阈值
```

方案一是基线。方案二在方案一基础上增加时相维度。两者共用预处理、特征提取、分类规则、窗户掩膜和验证流程。

> **本仓库的范围**:只实现**方案一**。方案二(多时相 + PCA + 配准)与其参数段未实现,
> 本文档中相关章节(§1.1 的方案二列、§1.2 ⑤、§3、§6 `run_pca`、§8)仅作原始设计存档。
> 另:本项目在方案一之上新增了**边界带**(§2.5)、**形状渗漏规则**(§4)、**`display` 段**
> (§5.1)三项,原始设计中无此概念,已在下文就地标注。

## 1. 共用部分:数据采集与预处理

### 1.1 数据采集

| 项 | 方案一(基线) | 方案二(升级) |
|---|---|---|
| 时相数 | 1 张 | 3~4 张(日出/上午/下午/傍晚) |
| 拍摄时机 | 晴日下午抓空鼓;雨后清晨抓渗水 | 晴天全天,覆盖升温+降温 |
| 飞行 | 单次 | 同一航点重复飞,位置角度一致 |

| 天气 | 晴天低风 | 晴天无云低风 |

### 1.2 预处理(共用)

```
① 读辐射温度:DJI Thermal SDK 读 R-JPEG → T(x,y) ℃
② 发射率校正:统一 ε=0.90(后续按砖0.90/混凝土0.92细分)
③ 去噪:3×3 中值/高斯
④ 算 GSD:Mavic 3T 约 D/540 m/px
⑤ (方案二额外)配准:可见光求单应,对齐所有时相到 T1
```

## 2. 方案一:基线管线(单帧)

```
① 去趋势: T_anom = T − 高斯模糊(T, σ),σ=2~3×缺陷半径(px)
② 稳健噪声: σ_noise = MAD(T_anom)×1.4826
③ 标准化: z = T_anom / σ_noise
④ 阈值: |z|>2.5,正=热斑(空鼓候选),负=冷斑(渗水候选/窗户)
⑤ 连通域,剔除面积<25px
⑥ 特征提取+分类(见第4节)
```

## 2.5 边界带:照片边界当作墙(本项目新增)

照片最外 `border_ignore_px`(默认 15)px 视为墙,**不参与检测**。动机:窗外未拍全、边界外
无墙可比,会在画面边缘产生大量伪影(实测某真实帧 43 个斑块里 16 个触及边界,其中 12 个挤在
左边缘 `x=0`)。

**实现口径:只作用于检测掩膜,不改像素值。** 不用"图像外扩 + 外扩区填墙面温度"的做法——
四边的墙面温度本来就不一致(实测四边中位数相差 4.12℃),填任何常数都会在边界造出阶跃,
反而把边界伪影炸开(实测斑块数 40→101→191),而且垫边会改变 MAD 噪声估计。

**关键:边界带是"检测口径",不是"形状口径"。** 斑块只要在带内有足够像素就会被检出,
但报出的形状取自它所属的**完整**连通域。原因:带会把跮过它的斑块轮廓沿直线切直,把
`rect`/`elong` 人为拉高(实测同一斑块 rect 0.66→1.00、elong 1.91→6.00)。回查完整连通域后,
跑出画面的细长渗漏能按真实形状判出来,而边界切出来的直边不会被当成矩形;同一完整连通域
被带切成两段时只报一次。

`border_ignore_px: 0` = 不过滤(旧行为)。

## 2.6 绝对矩形掩膜法(**调试用**,本项目新增)

由 `rect_mask.enabled`(0/1)控制,用来单独观察"纯几何找矩形"这一路的效果。
**判据是绝对的**:阈值是℃,不依赖噪声统计,也不做局部背景扣除——这正是它与
窗户掩膜(§4,走 z 分数 + 形态学)的分工差别。

```
二值 = |T − median(T)| > dt_c          转码:直接对图片生成二维二值矩阵(双侧,冷热都取)
规则 = 轮廓四边逼近 恰 4 顶点 且 凸
       且 四角与 90° 偏差 ≤ angle_tol_deg
       且 面积 ≥ min_area_px 且 短边/长边 ≥ min_side_ratio
粗边 = 矩形内前景像素到最近背景像素的最大距离 ×2 ≥ min_edge_px
掩埋 = 四边形填充成掩膜 → 膨胀 dilate_px → NS 修复填平 → 沿用原方案继续去噪等处理
```

**"粗边"是后加的一条判据。** 光有"四边逼近恰 4 顶点"这一条,一条 **1px 粗的细线框**
同样能凑出 4 个顶点被当成规则矩形。粗边判据把"有厚度"变成可量化的一条线,量的是
**最粗处**(2 × 最大内切圆半径):粗边框量到的是**带宽**,实心块量到的是**短边**,
同一把尺子。**实心矩形与粗边框都算**——判据是"边够粗",不是"必须是环形"。

实测:1px 细线框 = **2.0px**;真实窗框/实心块 = **14~92px**;直角处两个方向都通、
内切圆更大,故角部比带宽多 1~2px(8px 带宽量到 10px)。

> ⚠ **`min_edge_px` 在现有数据上从未生效过。** 真实帧上 `dt_c` 从 0.3 扫到 4.0,
> 四边候选的边宽最小也有 14px。它是**防发丝细线的护栏,不是当前的主力判据**。

**`dt_c` 是本方法的主要调节旋钮,取值影响很大。** 实测参考:

| 数据 | `dt_c` | 结果 |
|---|---|---|
| 合成场景(ΔT=−1.5℃ 的 80×80 冷方块) | 0.5 | 1 个矩形,正好命中方块 |
| 合成场景(同上,抬高成热方块) | 0.5 | 1 个矩形(双侧口径,冷热都取) |
| `demo.make_scene()` | 3.0 | 1 个矩形,正好命中那个窗户 |
| 真实帧 640×512 | 1.0 | 3 个矩形,二值占比 26% |
| 真实帧 640×512 | 2.0 | 4 个矩形,二值占比 15.6% |
| 真实帧 640×512 | 3.0 | 3 个矩形,二值占比 9.7% |

**三个调试时容易踩的点**(记下来,不是设计约束):

- **`approx_eps` 决定能否凑出"恰 4 顶点"。** 在真实帧上取 2% 时,那三个窗户分别给出
  6/6/4 个顶点,会被"恰 4 顶点"否掉;取 5% 才收敛到 4 个。注意这是**那张图**上的观测,
  合成形状复现不出来(硬边方块本身就是 4 顶点轮廓),故只作为调试提示。
- **量粗边前必须先给二值矩阵补一圈 0。** `cv2.distanceTransform` 只认"最近的 0 像素",
  **不把画面外当背景**,贴着画面边的块会被量成整个宽度(实测左边那栋楼 89px 宽量出
  174px)。补零后贴着边的 40px 宽带量到 40px。
- **清单条数不等于目标个数。** 一个目标内部若有与周围反差较大的结构(如窗内暖色窗框
  形成的"十字"),会被切成 4 个四边,`count` 虚高;掩膜取并集,掩埋结果仍然正确。

**产出**:启用时额外写 `rect_mask.png`(掩膜图),并把矩形清单并进 `summary.json` 的
`rect_mask` 段(`count` + 每个矩形的 bbox / 四点坐标 / 面积 / 角偏差 / 长短比 / 填充率 /
**粗边宽度 `edge_px`**)。

## 4. 共用:特征提取与分类规则

对每个候选斑块提取:

| 特征 | 定义 |
|---|---|
| 局部温差 ΔT | 斑块内均值 − 外围环带均值 |
| 边界锐度 | 斑块边缘梯度幅值均值 |
| 内部均匀度 | 斑块内温度标准差 |
| 矩形度 | 面积/最小外接矩形面积 |
| 伸长率 | 长轴/短轴(`cv2.minAreaRect` 的 max/min,旋转不变) |

> 注:`伸长率`(特征 `elong`)与下面"形状渗漏"规则的 `seepage_rect_elong` 是**同一个量**,
> 只是分属两条规则——前者是 ΔT 规则的伸长率下限,后者是形状规则的纵横比下限。

初始判定规则(**按序判定,命中即返回**):

| 判定 | 条件 |
|---|---|
| 窗户(非缺陷) | 矩形度>0.85 且 明显偏冷 ΔT<−5℃(+可选"边界锐"条件,默认关) |
| **形状渗漏(本项目新增)** | **矩形度 > 0.80(`seepage_rect`)且 纵横比 > 2.0(`seepage_rect_elong`)——不看 ΔT** |
| 空鼓 | ΔT>+1.5℃ 且 矩形度<0.8 且 边界弥散(+可选条件,默认关) |
| 渗水 | ΔT<−1.5℃ 且 伸长率>1.5 且 长轴偏垂直(+可选条件,默认关) |
| 其余 | 误报/不确定,交人工复核 |

**形状渗漏规则说明**(本项目新增,不在原始设计中):规则的矩形形状比温差更能说明问题——
实测存在矩形度高、明显细长的规则渗水,却因 ΔT 不够冷(−0.96℃,过不了 `seepage_dt_c=-1.5`)
被丢进 reject。故新增此规则**不查 ΔT**。可选的 `seepage_shape_require_cold`(默认 `false`)
开启后叠加 `seepage_shape_dt_c`(默认 −0.8)下限。"长轴偏垂直"开关对**两条**渗水规则都生效,
否则会被形状规则静默绕过。

窗户掩膜(**本仓库的实际实现,与原始设计不同**):原始设计拟用"可见光目标检测 + 摄影测量
三维凹陷"交叉确认窗户位置——**该方案未实现**。本仓库实现的是**两遍式窗户掩膜**:从 z 冷侧用
比检测层更宽松的阈值找窗户区域(直接矩形路径 + 合并成排/成列窗户的区域块路径),掩膜按外接
矩形填充后**自适应生长**覆盖去噪/窗框导热造成的过渡带,再用 NS 修复谐波填平背景;第二遍在
净墙上检测,与掩膜覆盖率超过 `exclude_overlap` 的候选斑块直接排除。参数在 `window_mask` 段。

> 窗户区域块的**宽高比**受 `window_mask.aspect_min/aspect_max`(默认 0.15 / 6.67,互为倒数)
> 约束。原值 0.08/12.5 假设"渗水是实心细条、矩形度≈1,靠 rect 就能挡住",但实测有矩形度仅
> 0.44、宽高比 0.131(长/宽 7.6)的贯穿全画幅冷条被当成窗区块吃掉;真正的窗区块宽高比在
> 2~3 附近,故收紧。

## 5.1 输出/渲染参数(本项目新增)

`display` 段**不是检测参数,是渲染范围**:只控制 `overlay.png` 画哪些斑块,不参与任何检测

  不连续——这是刻意的,便于对着 CSV 核对。

## 6. 合并伪代码

```python
import numpy as np, cv2
from scipy import ndimage

# ===== 共用预处理 =====
def read_temps(paths):
    return [read_rjpeg_temp(p) for p in paths]   # 读 R-JPEG → ℃

Ts = read_temps(paths)                            # 方案一:len=1;方案二:len=N
Ts = [cv2.medianBlur(t.astype('float32'), 3) for t in Ts]

# 方案二:配准对齐到 T0
if len(Ts) > 1:
    for i in range(1, len(Ts)):
        H = homography(vis0, vis_i)               # 在可见光上求单应
        Ts[i] = cv2.warpPerspective(Ts[i], H, Ts[0].shape[::-1])

# ===== 特征提取(共用) =====
def extract_features(blob, T):
    ring = cv2.dilate(blob.astype('uint8'), np.ones((5,5))) & (~blob)
    dT  = T[blob].mean() - T[ring].mean()          # 局部温差
    edge = cv2.Laplacian(T, cv2.CV_32F)
    sharp = np.abs(edge[blob]).mean()              # 边界锐度
    uniform = T[blob].std()                        # 内部均匀度
    x,y,w,h = cv2.boundingRect(blob.astype('uint8'))
    rect = blob.sum() / (w*h)                      # 矩形度
    _, (MA,ma), ang = cv2.minAreaRect(blob.astype('uint8'))
    elong = MA / ma                                # 伸长率
    return dict(dT=dT, sharp=sharp, uniform=uniform,
                rect=rect, elong=elong, ang=ang)

def classify(f, sign):
    if f['rect']>0.85 and f['dT']<-5:  return 'window'
    if sign=='warm' and f['dT']>1.5 and f['rect']<0.8:  return 'hollow'
    if sign=='cold':
        # 形状渗漏(本项目新增):不查 ΔT
        if f['rect']>0.80 and f['elong']>2.0:           return 'seepage'
        if f['dT']<-1.5 and f['elong']>1.5:             return 'seepage'
    return 'reject'

# ===== 方案一:单帧基线 =====
def run_single(T):
    sigma = 20                                     # 按 GSD 定
    bg = cv2.GaussianBlur(T, (0,0), sigma)
    Tanom = T - bg
    mad = 1.4826 * np.median(np.abs(Tanom - np.median(Tanom)))
    z = Tanom / mad
    masks = {'warm': z>2.5, 'cold': z<-2.5}
    return detect(masks, T)

# ===== 方案二:多时相+PCA =====
def run_pca(Ts):
    X = np.stack(Ts, axis=0).reshape(len(Ts), -1).T   # (M,N)
    Xc = X - X.mean(axis=1, keepdims=True)
    U, S, Vt = np.linalg.svd(Xc, full_matrices=False)
    H, W = Ts[0].shape
    results = []
    for k in [1, 2]:                              # 跳过 PC1
        score = U[:, k].reshape(H, W)
        mad = 1.4826 * np.median(np.abs(score - np.median(score)))
        z = score / mad
        masks = {'warm': z>2.5, 'cold': z<-2.5}
        results += detect(masks, Ts[0])           # 特征仍用 T 计算
    return results

# ===== 候选提取+分类(共用) =====
def detect(masks, T):
    out = []
    for sign, mask in masks.items():
        n, labels = cv2.connectedComponents(mask.astype('uint8'))
        for i in range(1, n):
            blob = labels == i
            if blob.sum() < 25: continue
            f = extract_features(blob, T)
            out.append((classify(f, sign), f, blob))
    return out
```

## 8. 切换条件

> **本仓库未实现**:下表是"方案一 / 方案二怎么选"的原始设计;本仓库只有方案一,
> 故第 2~4 行不适用。

| 情况 | 动作 |
|---|---|
| 单帧对比度足够,检出率/误报达标 | 用方案一即可 |
| 单帧对比度不足(阴天/冬季/窗户与缺陷混淆) | 上方案二 |
| 方案二配准失败或天气不允许多时相 | 退回方案一 |
| 两方案结果不一致的区域 | 以人工复核+可见光/三维为准 |

方案一是基线,方案二作为对比与升级,两者最终都输出到同一套分类规则和验证流程。
