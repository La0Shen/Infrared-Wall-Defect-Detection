# 《外墙热红外缺陷检测方案》

---

## 关键词

| 词 | 解释 |
|---|---|
| 空鼓 | 外墙瓷砖/抹灰层与墙体脱开,中间夹着一层空气。拿锤子敲会有"空、空"的响声。 |
| 渗水 | 水渗进墙体。常见于裂缝、防水层失效处,墙体会发霉、起皮。 |
| 热红外 | 物体都有温度,温度越高发出的红外线越强。热像仪接收红外线并换算成温度,拍成一张"温度照片"。 |
| R-JPEG | 大疆无人机的专用照片格式:看起来是普通照片,其实每个像素都额外记录了温度。 |
| 发射率 ε | 物体"发出红外线的能力"(0~1)。测温度必须按材质设对 ε,设错了读数就偏。 |
| GSD | 照片中一个像素对应墙面上多大的实际面积(米/像素)。Mavic 3T 约为"拍摄距离÷540"。 |
| 去趋势 | 从温度图里减掉"大范围平滑的背景",只留下"局部异常"。好比把照片底色洗掉,让上面的字露出来。 |
| MAD | 一种估算噪声强度的办法,不容易被个别极端值带偏(×1.4826 是为了换算成常用尺度)。 |
| z 分数 | "异常强度÷噪声强度"。z=2.5 表示异常比噪声强 2.5 倍,基本不可能是巧合。 |
| PCA | 把多张照片的温度变化自动拆成几种"基本模式",把"大家都一样的变化"和"少数区域才有的变化"分开。(**本仓库未实现**) |
| 配准 | 把角度略有差异的多张照片"掰对齐",让同一个墙面位置在每张照片里都是同一个像素。(**本仓库未实现**) |
| 边界带 | 照片最外一圈当作"墙",不参与检测。窗外没拍全、画面边缘没有旁边的墙可比,容易出假斑块。 |
| 形状渗漏 | 不看温差、只看形状的渗水判定:又方又细长的冷斑,形状本身就说明是渗水缝。 |
| display | 只管"叠加图上画哪些斑块"的一组开关,不影响 CSV/JSON/掩膜文件。 |
| 绝对矩形掩膜 | 另一种找矩形的办法:先把图**转码**成"与全墙中位数差了几度"的黑白图,再从中挑出"规规矩矩的四边形"填掉。不看"异常比噪声强几倍"。**调试用**。 |
| 粗边矩形 | 挑出来的四边形还得"边够粗"——一条头发丝那么细的方框线,也算"规规矩矩的四边形",但不是这里要的。量的是**最粗处**:空心方框量到边框的宽度,实心块量到短边。 |

> 名词表是原文没有的,为了通俗理解而补充。

## 一、要解决什么问题(背景)

- 外墙两大病害:
  - **空鼓**:饰面层与墙体脱开,严重时成片掉落,砸伤人和物。
  - **渗水**:水进墙体,霉变、起皮、钢筋锈蚀,缩短建筑寿命。
- 传统检查办法的痛点:
  - 空鼓靠人工敲击听声音——慢、累、主观(各人听感不同)、高楼外立面够不着、有坠落风险。
  - 渗水靠雨后肉眼找痕迹——看天气脸色,轻微渗水根本看不出来。
- 新思路:无人机飞一圈,用热红外相机拍下整面墙的"温度照片";温度异常的地方十有八九是缺陷。机器自动圈出来,人再到现场核实。

---

## 二、为什么温度异常 ≈ 缺陷(原理)

1. 所有物体都辐射红外线,温度越高辐射越强 → 热像仪把红外线"翻译"成温度图(每个像素一个温度值)。
2. **空鼓为什么发"热"**:脱空处夹着一层空气,空气是隔热层,把饰面层与基层**热隔离**。基层混凝土是个大热汇,正常墙面的热量能导进基层散掉;脱空处的热量导不出去,只好在饰面层表面**积聚**。所以不能只说"隔热",要说清后果:**脱空处的热惯量比正常墙面小**,对温度变化**响应更快、幅度更大**。
   - **升温时段**(白天太阳晒):它比正常墙面**热**(实测高 1~3℃),温度图上呈**热斑**。
   - **降温时段**(傍晚/夜间):它散热也更快,反而**冷**于正常墙面,呈**冷斑**——**符号随时相翻转**。
   - **现场仍以"晴天下午抓空鼓"为主**:降温段的温差通常更小、可用时间窗更窄,且要求低风速(≤4 m/s,风会把两边的温差一起吹平)。
3. **渗水为什么发"冷"**:水蒸发会吸热,湿墙表面温度比干墙低 → 表现为"冷斑"。注意这里有两个反向的效应:水的比热容大,湿墙**热惯量增大**(白天升温更慢→偏冷);蒸发吸热**始终**让表面偏冷。夜间热惯量项会把湿墙推向偏暖、与蒸发项反向,故渗水以**雨后蒸发旺盛时段**(清晨)为准。
4. 所以核心任务变成:在温度图里找"比周围明显热/冷的小块区域"。
5. **时机很重要**:晴天下午太阳晒足,空鼓温差最大;雨后清晨墙体还湿,渗水温差最大。拍对时机,缺陷自己"浮出来"。(原文 §1.1)

## 三、整体思路(原文 §0)

> **本仓库的范围**:下图里"方案二(升级)"这一支**未实现**。本仓库只做方案一,并在此之上
> 新增了边界带(§6.1 ⑥、§6.3)、形状渗漏规则(§8.2)、`display` 段(§6.3)。

```
                 R-JPEG 辐射温度
                      │
              共用预处理(读温/发射率/去噪/配准)
                      │
        ┌─────────────┴─────────────┐
        │                           │
   方案一(基线)                 方案二(升级)
   单帧处理                     多时相+PCA
        │                           │
   去趋势→阈值→特征分类        PCA→分量选择→阈值
        │                           │
        └─────────────┬─────────────┘
                      │
              共用:特征提取/窗户掩膜/分类规则
                      │
              地面真值验证 → 回调阈值
```

图上五个关键点:

1. **入口**:无人机拍的带温度的照片(R-JPEG)。
2. **共用预处理**:像"洗照片",两条路都要先做(第六、七节各自展开前都要经过这里)。
3. **两条并行分支**:
   - 方案一(基线):只拍 1 张,找静态温度异常。简单、要求低,先保证能用。
   - 方案二(升级):同一位置拍 3~4 张(早中晚),看温度"怎么随时间变",区分能力更强。
4. **共用出口**:两条路找到的可疑区域,都走同一套"画像 + 分类 + 窗户排除"流程。
5. **闭环**:现场验证 → 回调阈值,越用越准。

一句话总结:拍照 → 洗照片 → 找异常(两条路任选)→ 画像分类 → 现场验证 → 回调参数。

## 四、第一步:照片怎么拍(原文 §1.1)

### 4.1 两种拍法对比

| 项目 | 方案一(拍 1 张) | 方案二(拍 3~4 张) | 为什么这么要求 |
|---|---|---|---|
| 时相数 | 1 张 | 3~4 张(日出/上午/下午/傍晚) | 方案二要观察一整天的温度变化过程 |
| 拍摄时机 | 晴天下午抓空鼓;雨后清晨抓渗水 | 晴天全天,覆盖升温+降温 | 温差最大的时刻缺陷最明显 |
| 飞行 | 单次 | 同一航点重复飞,位置角度一致 | 保证各时相像素对得上 |
| 相机设置 | 固定 ε=0.90、关自动增益、固定量程 | 同左,且各时相完全一致 | 自动调节会让各张照片的"温度尺子"不一样,没法互相比较 |
| 天气 | 晴天低风 | 晴天无云低风 | 云会遮阳,风会加快散热,温差变小 |

### 4.2 两个通俗要点

- 相机设置的关键是"**一致性**":所有照片用同一把温度尺子,才能互相比较。
- 拍摄时机是关键变量:时机选对,温差 2~3℃;时机不对,缺陷与正常墙面温度几乎一样,再好的算法也难分辨。

## 五、第二步:照片怎么处理(共用预处理,原文 §1.2)

五道工序,像"洗照片":

| 工序 | 做什么 | 为什么 |
|---|---|---|
| ① 读温度 | 从 R-JPEG 里读出每个像素的温度 T(x,y) | 得到真正的"温度图",而不是普通照片 |
| ② 发射率校正 | 统一按 ε=0.90 换算(后续再按材质细分:砖 0.90/混凝土 0.92) | 不同材质"发出红外线的能力"不同,不校正温度会整体偏移 |
| ③ 去噪 | 用 3×3 中值/高斯滤波磨平噪点 | 热像仪有随机噪声,不处理会误报出"假异常" |
| ④ 算 GSD | 记录每个像素代表的实际大小 ≈ 距离/540 | 后面算缺陷面积、设定阈值都要用它 |
| ⑤ 配准(仅方案二) | 用可见光照片算出单应矩阵,把各时相温度图对齐到第一张 | 像素对不齐,"时间变化"就无从谈起 |

## 六、方案一(基线):单张照片怎么找异常(原文 §2)

**核心思想**:缺陷是"局部"的异常。把整面墙的"大背景"(整体明暗趋势)减掉,剩下的就是"局部突起"。

### 6.1 六个步骤

| 步骤 | 公式 | 大白话 |
|---|---|---|
| ① 去趋势 | T_anom = T − 高斯模糊(T, σ) | 原图减去"大范围平滑背景"。σ 设为缺陷半径的 2~3 倍,保证模糊时恰好把缺陷"抹掉"、背景留下 |
| ② 算噪声 | σ_noise = MAD(T_anom)×1.4826 | 估计"正常波动"有多大,作为比较的尺子 |
| ③ 标准化 | z = T_anom / σ_noise | 异常强度除以噪声强度,得到"异常分"。z=+3 表示比正常波动强 3 倍 |
| ④ 阈值 | \|z\|>1.5 | 只有明显异常才要:z 为正=热斑(空鼓候选);z 为负=冷斑(渗水候选或窗户) |
| ⑤ 连通域 | 剔除面积<50px 的斑块 | 把相邻的异常像素连成一片一片;太小的多半是噪声,扔掉 |
| ⑥ 边界带 | 照片最外 15px 当作墙 | 画面边缘没有旁边的墙可比,容易出假斑块,那一条不判决 |
| ⑦ 特征+分类 | 见第八节 | 给每个斑块"画像",判断它是什么 |

> ④⑤ 的数值是本仓库 `config/defaults.yaml` 的**现值**(原始方案初值为 z>2.5 / 25px,
> 已按第十一节的闭环现场回调);σ、MAD 那些是公式,不随回调变。

### 6.2 通俗比喻

把整面墙的温度图想象成一张印着深浅底色的纸(整体温度分布)。用模糊把它整张"洗淡",剩下的就是清晰的"局部印记"——这些印记就是要找的候选缺陷。

### 6.3 本仓库新增的三条工程规则(原文没有)

原始的方案一只有"去趋势→阈值→分类"。本仓库在真实无人机照片上调参时,陆续补了三条:

| 规则 | 解决什么问题 | 一句话原理 |
|---|---|---|
| **边界带**`border_ignore_px` | 画面边缘冒出大量假斑块 | 最外 15px 当作墙、不判决。只扣检测掩膜,**不改像素值**——往外垫一圈背景色反而会在边界造出温度阶跃,把伪影炸得更多 |
| **形状渗漏**`seepage_rect` / `seepage_rect_elong` | 又方又细长的规则渗水漏检 | 矩形度高 + 纵横比大 → 直接判渗漏,**不看温差**。规则形状比温差更能说明问题 |
| **`display` 段** | 叠加图上白框噪声太多,看不清真缺陷 | 按类别控制 `overlay.png` 画哪些斑块。**只影响这张图**,CSV/汇总/掩膜文件仍是全量 |

> **边界带有一个反直觉的细节**:它只管"在哪儿检测",不管"形状怎么量"。被它切过的斑块,
> 外轮廓会被沿直线切直,把矩形度、伸长率人为拉高。所以形状要回到**完整**的那个连通域去量,
> 否则边界会凭空"造出"细长的矩形。

## 七、方案二(升级):多张照片看"变化模式"(原文 §3)

> **本仓库未实现**:本节描述的是原始设计中的"方案二"(多时相 + PCA + 配准),本仓库只做
> 方案一,保留本节仅作存档。下一节(§八)讲的特征与分类规则**两条方案共用**,是实现的。

**核心思想**:不同物体的温度随时间变化方式不同——正常墙跟着太阳走;空鼓区因空气层隔热、**热惯量小**,对温度变化**响应更快、幅度更大**(见 §二.2);渗水区蒸发吸热,全天偏冷。多拍几张,就能把它们分开。

### 7.1 七个步骤

| 步骤 | 公式 | 大白话 |
|---|---|---|
| ① 堆数据 | N 张温度图堆成矩阵 X(M×N) | M=像素数,N=时相数。每个像素有 N 个时间点的温度读数 |
| ② 中心化 | Xc = X − 每像素时间均值 | 减掉每像素自己一天的平均值,只保留"怎么随时间变" |
| ③ 分解 | SVD:Xc = U·Σ·Vᵀ | PCA 自动把变化拆成几种"基本模式"(主成分) |
| ④ 还原成图 | U 各列 reshape 回图像;Vᵀ 各行 = 时间载荷 | 每个主成分画成一张图,并配一条"一天中何时最强"的曲线 |
| ⑤ 丢弃 PC1 | 第一主成分 = 大家都同步变的部分(太阳周期、柱子、窗户等静态背景) | 扔掉的正是"噪音",保留的才是差异 |
| ⑥ 看 PC2、PC3 | 按时间载荷区分空鼓/渗水 | 空鼓模式(升温段偏热、降温段偏冷,**符号随时相翻转**)与渗水模式(蒸发段偏冷)在时间曲线上特征不同 |
| ⑦ 阈值+特征分类 | 对每个分量图:z = 分量/MAD,\|z\|>2.5,提取斑块,然后走第八节 | 与方案一同款操作,共用下游 |

### 7.2 通俗比喻

PCA 就像把一首合唱曲拆成不同声部:PC1 是主旋律(整面墙都在随太阳升温降温),PC2、PC3 是"走调的声音"(缺陷区域)。听出哪里走调,就找到了缺陷。

## 八、第四步:给可疑区"画像"并分类(原文 §4)

### 8.1 五个"长相指标"(特征)

| 特征 | 定义 | 大白话:它回答什么问题 |
|---|---|---|
| 局部温差 ΔT | 斑块内均值 − 外围环带均值 | 它比周围热/冷多少? |
| 边界锐度 | 斑块边缘梯度幅值均值 | 边缘是"一刀切"还是"渐渐过渡"? |
| 内部均匀度 | 斑块内温度标准差 | 内部温度是一致的还是杂乱的? |
| 矩形度 | 面积 ÷ 最小外接矩形面积 | 形状有多"方"? |
| 伸长率 | 长轴 ÷ 短轴 | 是细长条还是圆团? |

### 8.2 四条判定规则

| 判定 | 条件 | 大白话:凭什么这么判 |
|---|---|---|
| 窗户(非缺陷) | 矩形度>0.85 且 ΔT<−5℃(+可选"边界锐") | 很方、明显偏冷——这"长相"就是玻璃 |
| **形状渗漏**(本项目新增) | **矩形度 > 0.80 且 纵横比 > 2.0——不看 ΔT** | 又方又细长,形状本身就说明是渗水缝,不必再等温差 |
| 空鼓 | ΔT>+1.5℃ 且 矩形度<0.8(+可选"边界弥散") | 偏热、形状不规则、边缘模糊——符合脱空层积热的物理特征 |
| 渗水 | ΔT<−1.5℃ 且 伸长率>1.5(+可选"长轴偏垂直") | 偏冷、细长、竖着——水往下渗流的样子 |
| 其余 | — | 特征不明 → 交人工复核,不硬判 |

> **"可选"三项默认关闭**:原始设计的伪代码并未使用"边界锐利""边界弥散""长轴偏垂直"
> 这三个定性条件,本仓库实现为可选开关,默认关闭。别把它们当成生效条件。
>
> **判定按序进行,命中即返回**,所以上面的顺序有意义:形状渗漏排在窗户之后、空鼓与渗水
> 之前。"长轴偏垂直"开关对**两条**渗水规则都生效。

### 8.3 窗户怎么排除(本仓库的实际做法与原始设计不同)

- **原始设计**(未实现):用可见光照片做窗户目标检测 + 摄影测量验证"三维凹陷",双重确认
  后剔除。
- **本仓库实现的是"两遍式窗户掩膜"**:先从 z 冷侧用比检测层更宽松的阈值找窗户区域
  (既抓单个矩形窗,也把成排/成列的窗户合并成区域块),掩膜按外接矩形填充后**自适应生长**
  覆盖窗框导热与去噪造成的过渡带,再用 NS 修复把整块填成背景;第二遍在"净墙"上检测,
  与掩膜重叠过多的候选直接排除。窗户本身仍会报出,类别为 `window`。
- 为什么要专门做这件事:窗户在温度图上与渗水**同号**(都是冷斑),不排除会被大量误报成渗水。

## 九、所有"旋钮"参数一览(原文 §5)

| 参数 | 初值 | 本仓库当前值 | 大白话:这个旋钮控制什么 |
|---|---|---|---|
| 发射率 ε | 0.90 | 0.90 | 温度尺子的校准系数(按材质) |
| 去趋势 σ | 2~3×缺陷半径(px) | 20 px | 背景"抹多狠"。太小→缺陷被当背景抹掉;太大→背景残留造成误报 |

| 最小斑块面积 | 25 px | **50** | 噪声过滤:小于这个面积的异常一律无视 |
| 空鼓 ΔT | >+1.5℃ | 同 | 空鼓"要多热才算" |
| 渗水 ΔT | <−1.5℃ | 同 | 渗水"要多冷才算" |
| 窗户 | 矩形度>0.85 且 ΔT<−5℃ | 同 | 窗户"要多方、多冷才算" |
| **边界带宽度**(新增) | — | 15 px | 照片最外多少 px 当作墙、不参与检测 |
| **形状渗漏:矩形度**(新增) | — | 0.80 | 多"方"才算规则渗水 |
| **形状渗漏:纵横比**(新增) | — | 2.0 | 多"细长"才算规则渗水 |
| **形状渗漏:ΔT 门**(新增,默认关) | — | false / −0.8℃ | 开启后额外要求"也要够冷" |
| **窗区块宽高比**(收紧) | — | 0.15 / 6.67 | 窗区块不能比这更细长,更细长的按渗漏交给检测层 |
| **绝对矩形掩膜**(新增,调试用) | — | 开关 0/1、温差 2.0℃、最小边宽 3.0px | 按"与全墙中位数差几度"转码后挑规则**粗边**矩形;温度阈值是主要旋钮,边宽门槛只是防发丝细线 |
| PCA 保留分量 | PC2、PC3(先看 PC1~PC5) | **未实现** | 留下哪几个"声部"来分析 |

方案的规范初值,右列是本仓库 `config/defaults.yaml` 的现值——按第十一节的闭环现场验证后
回调过(z 阈值 2.5→1.5、最小面积 25→50)。**以 `config/defaults.yaml` 为准**。

## 十、代码逻辑速览(原文 §6)

伪代码分五大块,用大白话过一遍:

1. **预处理块**(read_temps / 中值滤波 / 配准):
   读入所有照片的温度图 → 中值滤波去噪 → 若方案二(多张),用单应矩阵把后续各张对齐到第一张。
2. **特征提取块**(extract_features):
   对每个斑块:算 ΔT(与外围一圈比温度)、边界锐度(拉普拉斯梯度)、内部均匀度(标准差)、矩形度(与外包矩形比面积)、伸长率(长轴÷短轴)。
3. **方案一函数**(run_single):
   高斯模糊当背景 → 原图减背景得异常 → MAD 估噪声 → z 分数 → 正负双侧阈值 → 出斑块。
4. **方案二函数**(run_pca):
   堆数据 → 中心化 → SVD → 跳过 PC1,对 PC2/PC3 各自:reshape 成图 → MAD → z 阈值 → 出斑块(特征仍在原始温度图上计算)。
5. **检测+分类块**(detect):
   对热斑/冷斑分别做连通域 → 剔除小面积 → 提取特征 → 分类(窗户/空鼓/渗水/待复核)。

要点:两条方案唯一的区别在"找斑块"一步,其余代码完全共用——这正是总体架构图里"共用部分"的意义。

## 十一、结果怎么验证、参数怎么回调(原文 §7)

| 验证对象 | 现场怎么做 | 看什么指标 |
|---|---|---|
| 空鼓 | 锤击听空响 | 检出率、误报率 |
| 渗水 | 雨后观察痕迹/湿度计 | 检出率、误报率 |
| 窗户 | 单独统计是否被正确判为非缺陷 | 窗户误报数 |

- 统计**检出率**(真缺陷找到了多少)和**误报率**(正常区域误报了多少)。
- 不达标就回调旋钮:z 阈值、ΔT 阈值、矩形度阈值、σ、保留分量数——回到第九节的参数表改初值,再跑一遍。
- 本质:这是一个"跑一遍 → 现场核实 → 调参数"的循环,数据积累越多,参数越准。

## 十二、两个方案怎么选(原文 §8)

> **本仓库未实现**:本节是"方案一 / 方案二怎么选"的原始设计。本仓库只有方案一,
> 故除第 1 行外都不适用。

| 情况 | 怎么做 | 大白话 |
|---|---|---|
| 单帧对比度足够,检出率/误报率达标 | 用方案一 | 一张照片就够,就别折腾多拍了 |
| 对比度不足(阴天/冬季/窗户与缺陷混淆) | 上方案二 | 单张分不清,就看时间变化 |
| 方案二配准失败或天气不允许多时相 | 退回方案一 | 进阶路走不通,基线兜底 |
| 两方案结果不一致 | 人工复核+可见光/三维为准 | 机器说不清的交给人 |

- 关系:方案一是保底基线,方案二是可选升级;两者最终都汇入同一套分类规则和验证流程。
