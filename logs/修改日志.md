**两个刻意的设计决定**(易被误改,勿动):

1. **编号沿用原下标,不重新编号**。`pipeline.py` 用同一个 `enumerate(defects)`

`"ture"` 是字符串(真)、`2`/`-1` 也会被 `bool()` 当真。`_check_display()` 因此显式

提示填 0/1),与 `_build` 的"防拼写错误静默回退"同口径。

**关键实测(推翻了字面方案)**:字面理解"图像外扩、外扩区填墙面温度"是**有害**的。
`test01` 四条边的墙面中位数相差 **4.12℃**(左20.00/上16.21/右16.44/下15.88),
填任何常数都会造出阶跃;且垫边把 MAD 噪声 σ 从 0.213 拉到 0.134–0.179,z 整体
放大。边界 20px 带内:

| 方案 | mean\|z\| | \|z\|>3 像素 |
|---|---|---|
| 现状 | 1.35 | 6387 |
| 垫边:全局中位数 | **3.79** | **15355** ↓变差 |
| 垫边:逐边局部中位数 | 2.71 | 13257 ↓变差 |
| 垫边:复制高斯背景 | 2.29 | 11643 ↓变差 |

且现状边界**无系统性偏差**(边界带温度 vs 背景只差 ±0.06℃),问题不在去趋势。
故改为**只在检测掩膜上扣掉最外一圈,不动像素值**。

**第二个实测发现(两项改动的相互作用)**:边界带会把跮过它的斑块轮廓沿直线
**切直**,人为拉高 `rect`/`elong`——同一斑块 `(617,84,23,43)` 在 `border_px=15`
下变成 `(617,84,8,43)`,`rect` 0.66→**1.00**、`elong` 1.91→**6.00**。若不处理,
形状渗漏规则会被边界凭空喂进细长矩形:test01 上新增的 6 个 seepage **全部**
距边界 15–24px。故新增 `touches_border()`,被切过的斑块不参与形状规则。

**三条刻意的设计决定**(易被误改):

1. **边界带只作用于检测掩膜,不作用于窗户掩膜**。窗户掩膜是"删除+修复"机制,
   在那里裁剪会让补丁起点从 x=0 挪到 x=15,`_inpaint_windows` 覆盖不到 0–14 列,
   实测 `temperature.npy` 边界留下 **4.1℃** 的冷条(overlay 上可见接缝),且对
   那两个大窗区块毫无作用。当前实现下 `border_px=0` 的输出与改动前逐字节一致。
2. **`keep` 在 `run_single` 里只构造一次**,位置在 `gsd()` 之后。`T` 随后被
   `_inpaint_windows` 重新赋值但形状不变,故 `keep` 全程有效,无需重建。
3. **"长轴偏垂直"开关对两条渗水规则都生效**(抽出 `_vertical_ok`)。
   否则开关名字写着"渗水必须竖直",却被形状规则静默绕过。

**行为变更(默认值)**:`border_ignore_px` 默认 15、形状渗漏规则默认开启,故
**默认输出与 B 节不同**——B 节"检测层未受影响"的说法自本节起不再成立,
本轮**有意**改动了检测层。逐项验证:

  与改动前**逐字节一致** —— 证明两项改动没有互相渗透、也没有顺手改别的东西。
- `border_ignore_px: 0`(仅关边界带)时 bbox 集合与改动前完全相同,仅 3 个
  标签由 `reject` 翻成 `seepage`(形状规则所致)。

  `(401,81)`/`(336,82)`/`(526,83)` 全部保留;唯一真渗水 `(308,120,23,3)`

- `pytest` 55 项全绿。

**诚实记录:形状规则在 test01 上没有可证实的真阳性**。关掉边界带时它把 3 个

## D. 边界带改为"检测口径" + 窗区块长宽比收紧(2026-09-17)

**动机**:用户给出 test01 的真值——`#4 (272,366,368,146)` 是**真窗**(右侧凹进去
那块也是窗户),`#3 (58,0,67,512)` 是**渗漏**。C 节的两项改动都判错了:前者被
`window_mask` 块路径吃掉、后者被 C 节自己加的"被边界带切过就排除"规则打成
`reject`。

**先试了用户提议的方案并否决**:用户提出"在边缘拼接一圈背景色,输出时删除"。
实测该方案**有害且无效**——背景色与边界墙面之间必然有阶跃(四边墙面中位数
相差 4.12℃),垫边把边界伪影炸开:

| 垫边宽度 | 斑块总数 | #3 | #4 |
|---|---|---|---|
| 不垫边 | 40 | window | window |
| 40px | 27 | **消失** | **消失** |
| 80px | **101** | **消失** | reject |
| 150px | **191** | hollow | reject |

没有任何宽度能恢复 #3/#4,故不采用。

**改动文件**:

| 文件 | 改动 |
|---|---|
| `src/thermal_inspect/pipeline.py` | `run_single`:检测仍在边界带扣过的掩膜上做,但形状回查**完整**连通域(每个极性只标注一次,同一连通域被带切成两段时只报一次);bbox/area 也取完整连通域 |
| `src/thermal_inspect/classify.py` | 删掉 C 节新增的 `border_clipped` 参数(被"回查完整连通域"取代) |
| `src/thermal_inspect/detect.py` | 删掉 `touches_border()`(同上,不再需要) |
| `src/thermal_inspect/config.py` | `window_mask.aspect_min` 0.08→0.15、`aspect_max` 12.5→6.67(互为倒数) |
| `config/defaults.yaml` | 同步上述两个值;注释记录原假设为何不成立 |
| `tests/` | 新增/改写边界与形状用例;总数 55→53 |
| 文档 6 处 + `logs` 本文件 | 规则表/调参表/注意事项/用例数 |

**两个核心设计决定**:

1. **边界带是"检测口径",不是"形状口径"**。带会把跮过它的斑块轮廓沿直线切直、
   把 `rect`/`elong` 人为拉高(实测同一斑块 rect 0.66→1.00、elong 1.91→6.00)。
   故:检测在扣过的掩膜上做(边界伪影照样清掉),形状回查完整连通域。两个方向
   都要成立——既能判出跑出画面的真渗漏,又不会把边界切出来的直边当成矩形:

   | 斑块 | 切过的掩膜 | 完整连通域 | 真值 |
   |---|---|---|---|
   | #3 渗漏 | rect 0.83 elong 13.85 | rect 0.83 **elong 14.31** | 渗漏 ✓ |
   | 边界伪影 | rect **1.00** elong **6.00** | rect **0.67** elong **1.91** | 非渗漏 ✓ |

2. **收紧窗区块长宽比,而不是降 `close_kernel`**。用户指出"用长宽比,这个明显的
   长宽比为渗水"。`close_kernel` 从 11 降到 7 也能让 #3 不被掩,但那会削弱块路径
   合并成排窗户的能力;#3 的宽高比 0.131(长/宽 7.6)本身就与"成排窗户合并出的
   块"(实测真窗区块在 2~3 附近)差一个量级,故直接收紧 `aspect_min/aspect_max`。
   原注释假设"渗水是实心细条 rect≈1,靠 rect 就能挡住"——实测 #3 的 rect 只有
   0.44,该假设不成立,已在注释中改正。

**行为变更与实测(test01,用户真值:#3 渗漏、#4 窗、3 个真窗)**:

- #3 `(87,45,34,467)` → **seepage** ✓、#4 `(272,366,368,146)` → **window** ✓;
  3 个真窗 `(401,81)`/`(336,82)`/`(526,83)` 保留;假窗 #3 消失(窗 5→4)。
- 形状渗漏规则默认(不查 ΔT)在 test01 上得 **7 个 seepage**,其中边界处 4 个是

## G. 绝对矩形掩膜法:改为「规则粗边矩形」(2026-09-18)

**动机**:用户原话——"修改功能，做调试用：修改绝对矩形掩膜法，即直接对图片进行转码，
生成二维矩阵，直接对其中**规则粗边矩形**进行掩埋处理，然后沿用原方案去噪等处理。
不要更改我的想法，我只是做调试用。"

与 F 节的差别只有一个词:**粗边**。F 节的判据是"轮廓四边逼近恰 4 顶点 + 凸 + 四角近
90°",但一条 **1px 粗的细线框**同样能凑出 4 个顶点,会被当成规则矩形。"粗边"把
"有厚度"变成可量化的一条线。

**口径先问清楚再动手**(AskUserQuestion):给了三个选项——(a) 必须是环形(有孔洞)+
边宽达标;(b) 实心矩形也算,只加一道厚度门槛;(c) 两种分开统计。**用户选了 (b)**。
故不做"必须有孔洞"的要求,也不加 `kind` 字段。

**改动文件**:

| 文件 | 改动 |
|---|---|
| `src/thermal_inspect/rect_mask.py` | 补零后算 `cv2.distanceTransform`;新增粗边判据;清单新增 `edge_px` |
| `src/thermal_inspect/config.py` | `RectMaskParams.min_edge_px: float = 3.0`(浮点键不校验,与 `detrend_sigma_px` 同口径);类 docstring 补"规则 = …,粗边 = …" |
| `config/defaults.yaml` | `min_edge_px: 3.0` + 注释 |
| `src/thermal_inspect/pipeline.py` | 文案"规则矩形"→"规则粗边矩形"(docstring / 控制台 / summary 的 note) |
| `tests/test_rect_mask.py` | +4 项;`tests/test_config.py` 的浮点契约清单加 `min_edge_px` |
| 文档 6 处 | §2.6、§5 参数表、算法说明第 9 条、通俗版(名词表 + 参数表)、思维导图、README;用例数 66→70 |

**算法(只在 F 节的判据上加一条,其余不动)**:

```
二值 = |T − median(T)| > dt_c          转码:直接生成二维二值矩阵(绝对温差,双侧)
规则 = 轮廓四边逼近 恰 4 顶点 且 凸 且 四角与 90° 偏差 ≤ angle_tol_deg
       且 面积 ≥ min_area_px 且 短边/长边 ≥ min_side_ratio
粗边 = 矩形内前景像素到最近背景像素的最大距离 ×2 ≥ min_edge_px     ← 本轮新增
掩埋 = 四边形填充成掩膜 → 膨胀 dilate_px → NS 修复填平 → 沿用原方案继续去噪等处理
```

**粗边怎么量**:2 × **最大内切圆半径**。粗边框量到的是**带宽**,实心块量到的是**短边**,
同一把尺子;直角处两个方向都通、内切圆更大,故角部比带宽多 1~2px(8px 带宽量到 10px)。
两个坑都是实测踩出来的:

- **必须先给二值矩阵补一圈 0**:`cv2.distanceTransform` 只认"最近的 0 像素",**不把画面外
  当背景**,贴着画面边的块会被量成整个宽度——实测左边那栋楼 89px 宽量出 **174px**。
- **必须只在四边形范围内的前景像素上取**:若在填充后的整个矩形上取,粗边框量到的会是

## J. 窗形渗漏保护:极端狭长的疑似窗户块,查内部温度分布再定性质(2026-09-19)

用户报告:**test02 把渗漏识别成了窗户**。真值经用户确认:被误判的那一块是**画面左侧
贯穿全高的竖直冷条**(overlay 上的 `0:window`,x≈86~127)。

### 一、故障机制(test02 实测)

窗户掩膜的**块路径**为了把成排/成列的窗户合并成块,接受 `rect ≤ 0.85` 且宽高比落在
`[0.15, 6.67]` 的冷块。一条**连续均匀的细长冷带**也落在同一个接受域里:

```
z<-1.5 原始冷块(未闭运算)  41×378  长宽比 9.2    ← 真实物体
闭运算 11 与邻栋楼冷碎块合并后 bbox 131×512  宽高比 0.256  rect 0.307
  → 块路径接受 → 整块按外接矩形掩掉 → 渗漏从缺陷清单里消失
```

`test02` 加保护前:`{'window': 2, 'reject': 85}`,**零渗漏**;另一个 window 是中部
的窗排(真窗户,不该动)。

### 二、判据:用户提的"内部温度是否均衡",实测发现**标准差判不开**

用户原话:"若内部温度均衡,则不将其作为窗户;若不均衡,则将其作为窗户"。先按最直白的
口径量(块内像素温度):

| 块 | std(℃) | IQR(℃) | p95−p5(℃) | 高通 std(℃) |
|---|---|---|---|---|
| test02 左柱(渗漏) | **0.560** | 0.893 | 1.67 | 0.151 |
| test02 中部窗排(窗户) | **0.529** | 0.670 | 1.79 | 0.146 |

**几乎相同,判不开**。原因:左柱沿长度方向有 15.3→16.4℃ 的缓变,把"温度的绝对离散度"
撑到了与真窗排同一量级。test01 上更没区分度(所有冷块 std 0.35~0.56,窗排 0.53)。
结论:**要判的不是"温度离散度",而是"内部有没有结构"**。改成两条口径(两条**都成立**
才算均衡,保守取向——任一条看出结构就仍按窗户):

| 块 | ① 外接框内 z>1.5 占比 | ② 块内 \|∇T\|>0.85σ 占比 | 判决 |
|---|---|---|---|
| test02 左柱(渗漏,长宽比 9.43) | 0.009 | 0.0000 | 均衡 → **渗漏** |
| test02 中部窗排(窗户,长宽比 2.52) | 0.285 | 0.0141 | 有结构 → 窗户 |
| test01 窗区块(长宽比 2.72) | 0.292 | 0.0000 | 长宽比不过门槛,不进判据 |
| test01 三窗(1.14 / 1.69 / 1.71)、demo 窗(1.33) | — | — | 同上 |

①(值域分布):窗排内部有**明显更暖的子结构**(室内暖色透过玻璃,玻璃反光也是暖的),
均匀冷带没有。②(空间分布):窗排内部有**窗框/格栅/反光边界**这类强边缘,均匀冷带
内部完全平滑(左柱 0.0000 是因为它是一整条均匀冷带;中部窗排 0.0141 全来自窗框)。

**门槛**:极端狭长取 `elong_min=4.0`(实测窗排/窗区块 1.1~2.7,误判冷带 9.43);

### 三、判"主导原始冷块",不判闭运算块

闭运算块是块路径**合并出来的产物**,形状不代表任何真实物体(左柱:原始 41×378 / 9.2:1,
闭运算后 131×512 / 3.9:1)。而"三段错位窗扇合并成的块"(`test_pipeline.py::
test_window_mask_block`)每个窗扇本身只有 2:1。按原始冷块判,两者自然分开:**合并出来的
块不算狭长,连续的一根才算**——正好对上"块路径是为了合并成排窗户"的初衷。

## L. 窗户/渗漏判据加一条通道:边缘十分规整 → 也视为窗户(2026-09-19)

用户要求(原话):**"为刚才检验窗户是否为渗漏的算法多加一个通道:若这个疑似为窗户的
物体边缘十分规整,则也视为窗户"**。

### 一、加在哪、判据是什么

J 节那条保护的逻辑原本是"极端狭长 **且** 内部温度均衡 → 不是窗户"。本次加**第三条
"是窗户"的口径**(与口径①②并列为"任一条成立就仍按窗户"):

    口径③ 边缘规整度 regularity = 最小外接矩形周长 / 轮廓周长 ≥ regular_min(默认 0.90)
           → 视为窗户,不释放

物理含义:窗户是人造的**直边**东西(玻璃、窗框、预制带窗),边界与它的最小外接矩形
贴合;渗水/潮湿是自然蔓延的**毛边**东西,边界比直边长一截。1.0 = 边界恰好就是那四条
直边。

### 二、为什么用"周长比"而不是"矩形度 rect"(实测把 rect 否掉)

先按最顺手的 `rect`(面积/最小外接矩形面积,项目里已有的量)量,发现分不开:

| 物体 | `rect` 矩形度 | 规整度(周长比) |
|---|---|---|
| test02 左柱(**真渗漏**) | 0.750 | **0.767** |
| 合成锯齿边冷条 | 0.918 | 0.759 |
| test01 真窗(`.JPG` 里三个窗之一) | 0.870 | **0.955** |
| 直边合成冷条 | 1.035 | **1.000**(夹到 1.0) |

`rect` 同时吃"边界毛糙"和"没填满外接矩形"两件事,对残留细缝特别敏感:真渗漏 0.750 与
锯齿合成条 0.918 只差 0.17,阈值没地方放。**周长比**直接量"边界是不是直的":真渗漏
0.767 / 合成锯齿 0.759 在一侧,真窗 0.955 / 直边 1.000 在另一侧。

### 三、门槛为什么是 0.90(不是 0.85)

用户原话是"边缘**十分**规整"。实测锚点:

```
test02 左柱(真渗漏)          0.767
合成锯齿条                    0.759 ~ 0.806
test01 那条有争议的竖直冷条    0.842   ← 0.85 离它太近,差点被这条通道救成窗户
test01 真窗                   0.955
直边合成条                    1.000
```

0.85 会让"有争议的那条(0.842)"贴着门槛,取 **0.90** 才配得上"十分":真窗(0.95)
稳在门槛之上,真渗漏(0.767)与那条争议条(0.842)都在门槛之下。

### 四、实测

**真实三帧(默认参数)**——口径③对现有数据**没有改变任何输出**,它拦的是"本该被释放
的直边物体"这几帧里没有:

test02  {'seepage': 1, 'window': 1, 'reject': 85}    ← 与 J 节一致,真渗漏没被救回去
test01  {'window': 4, 'reject': 39, 'seepage': 2}    ← 与 J 节一致

## M. 三条口径各配一个开关,放进 defaults.yaml 并标注(2026-09-19)

用户要求:**"把三个口径的开关放到 defaults.yaml 中并标注"**。

### 一、加了什么

`window_guard` 段新增三个开关(与 `enabled` 并列在段首,"口径开关"小块里):

```yaml
  warm_on: true                 # ①:内部有没有明显更暖的子结构(窗格/反光)
  edge_on: true                 # ②:内部有没有窗框/格栅那种强边缘
  regular_on: true              # ③:边缘十分规整(人造直边物)
```

语义:**关掉的那条口径不参与判决**(其余两条照旧;**三条全关** = 极端狭长且内部均衡的块
一律释放,只剩 `elong_min` 一道门)。**指标无论开关都照算**,数值仍打进控制台那行 `[info]`
——现场可以"先看数值,再决定要不要开这一条"。理由串里,关着的口径会标 `口径关闭`:

```
[info] 窗形渗漏保护:块 (...) 非窗户 → 渗漏(长宽比 9.43,暖结构 0.009(≤0.10),强边缘 0.0000(≤0.0050),规整度 0.767(<0.90))
                                                                    ↑ 该条口径若关着,这里会写 ",口径关闭"
```

开关写 `true/false`(或 YAML 常见的 `0/1` 都认,与 `display` 段的 `show_*` 同口径);
写成别的值**报错并带键名**(`window_guard 的 edge_on 必须为 true/false(或 0/1)`),
不静默当真——与 4 个开关共用的 `__post_init__` 校验一处管。

**关口径请用开关,不要再靠"把阈值设成 1.0 / >1"那套**:阈值把戏仍然有效(留着不动),
但那是"用一个数去表达一个开关",现场容易看错;段内已改写成指向对应开关。

### 二、加开关顺带暴露的一件事(测试里的真问题)

## O. 口径③改用"边缘拟合直线 + 不规则突出占比"(2026-09-19)

用户要求:**"规整度的计算不要用最小外接矩形周长/轮廓周长;考虑边缘是否更拟合为一条直线
以及不规则突出的占比"**。

### 一、新口径

只对**极端狭长**的物体用(门槛 elong_min ≥ 4),所以边界模型很明确:**两条长边**。
做法(实现见 `window_guard.regularity()`,另有 `edge_fit_detail()` 只回两个原始量):

```
1. 用像素坐标 PCA 主方向摆正(长轴 u / 短轴 v),掐掉两端各 10% 的端盖(那是角部);
2. 长轴分 40 段,每段取最大/最小 v 作为上沿/下沿剖面,各自对 u 做**最小二乘直线拟合**;
3. 偏差 = 剖面上各点到各自拟合直线的距离(px)
     dev_px    偏差绝对值的平均   → "边缘到底像不像一条直线"
     prot_frac 偏差 > edge_tol_px 的占比 → "不规则突出/凹陷占多大比例"
   规整度 = (1 − clip(dev_px / edge_dev_ref_px, 0, 1)) × (1 − prot_frac)
```

默认:`edge_dev_ref_px = 1.0`、`edge_tol_px = 2.0`、`regular_min = 0.50`。

**为什么参照取绝对 px(1px),不按物体尺寸归一**:实测按宽度归一之后,15px 宽的窗间
墙柱(0.26px)与 31px 宽的真渗漏(0.96px)只差 1.8 倍,判不开——因为"直不直"是**栅格与
噪声**层面的事:一条直边无论多长多宽,边界都只该在 1px 内(像素化本身就有 ±0.5px 的
锯齿底噪)。这与项目其它 px 参数(`detrend_sigma_px` / `ring_kernel` / `dilate_px`)
同口径,同一台相机同一航线可比。

**为什么换掉旧口径**(`最小外接矩形周长 / 轮廓周长`,L 节那版):
1. 同一根直边带子,只要端点被噪声多啃进去几像素,比值能掉 0.1 以上——**对端盖过敏**,
   而端盖根本不是这条判据要看的东西;
2. 它把"边缘毛糙"和"没填满外接矩形"混在一个数里(与 `rect` 同样的毛病);
3. 实测旧口径在真实数据上挤在一起,新口径差一个量级:

| 物体 | 旧口径(周长比) | 新口径:偏离px / 超2px占比 → 规整度 |
|---|---|---|
| test04 窗间墙柱、横向接缝(人造直边) | 0.861 ~ 1.000 | 0.00~0.35px / 0.000 → **0.65 ~ 1.00** |
| test02 左柱(**真渗漏**,31×377) | 0.767 | 1.96px / 0.312 → **0.00** |
| test01 那条争议竖直冷条 | 0.842 | 1.04px / 0.188 → **0.00** |
| test04 (178,243,93,29) 冷斑 | 0.244 | 1.56px / 0.203 → **0.00** |

门槛 0.50 两头都不贴边(人造物最低 0.65,渗漏与毛糙冷斑一律 0.00)。

## R. 边缘口径的两个子口径拆成各自可开关(2026-09-19)

用户要求:**"把线性检测也作为参数加进去"** → 经确认,指的是把边缘口径的**两个子口径
拆开、各自可开关**(与 `window_guard` 三条口径的开关同款)。

### 一、加了什么

`config/defaults.yaml` 的 `seepage_guard:` 段新增:

```yaml
  line_on: true                 # 子口径①:上/下沿到最小二乘直线的平均偏离(边直不直)
  prot_on: true                 # 子口径②:偏离超 edge_tol_px 的占比(不规则突出占多大比例)
```

```
规整度 = 开着那几项的乘积
  ① 直线拟合度 = 1 − 平均偏离 ÷ edge_dev_ref_px
  ② 突出占比   = 1 − 超容差剖面点占比
两项都关 = 恒判"规整"(等于全部改判)
```

实现:`window_guard.regularity()` 加 `line_on` / `prot_on` 两个出参(默认都 True,
**默认行为与拆开之前逐位相同**——146 条既有用例全绿即是证据);`seepage_guard` 的参数与
理由串跟上,关掉一项时控制台会写明是"只算直线拟合"还是"只算突出占比"。原始的两个量
(`dev_px` / `prot_frac`)照旧一律算出来打进 `[info]`,便于"先看数值再决定开不开"。

### 二、为什么值得拆(实测分工)

同一条带鼓包的直边竖条,两个子口径的看法**不一样**:

| 形状 | ① 直线拟合 | ② 突出占比 | 两项都算 | 只算① | 只算② |
|---|---|---|---|---|---|
| 直边条(无鼓包) | 1.00 | 1.00 | 1.000 改判 | 1.000 改判 | 1.000 改判 |
| 直边条 + 6px 鼓包 | 0.00 | 0.50 | **0.000 维持渗漏** | 0.000 维持 | **0.500 改判** |

①看的是"整条边还直不直"(一个鼓包就把它拖到 0),②看的是"不规则的部分占多大比例"
(一个鼓包只占一小段)。两者都算取乘积 = 最保守;现场想单看哪一项说了算,关掉另一项即可。

  两项都关 = 恒判规整(踩坑口径,如实钉住)/ 0-1 写法与错误键名。
